# PGEN manifest and optional sample selection

The user requested a manifest-driven genotype input and an optional sample list. Use a headered TSV with exactly `chromosome`, `pgen`, `pvar`, and `psam`. `PgenManifest` replaces the workflow's `ChromosomePgens` input. Shared PSAM paths are allowed. Preserve row order, validate chromosome aliases and reject duplicates or missing fields. Genotype paths must be absolute cloud or local paths and are not opened by the planner.

Reuse the existing planner task. It receives the manifest as a typed File, validates it, and writes a headerless normalized TSV with both quoting and escaping disabled, so literal quote characters are preserved. WDL reads that small output and constructs an array of `ChromosomePgen` structs with typed File members before batch calls. The planner never localizes chromosome genotypes. This avoids a new VM and keeps input localization under Cromwell. No workflow-scope file writers or JSON argument wrappers are added. The old direct planner CLI with `--chromosomes-file` remains supported; the workflow uses `--pgen-manifest`.

When `SampleList` is absent, use the sample-ID intersection between the full extracted PGEN and the phenotype matrix, in PSAM order. Do not filter on phenotype values or silently use covariates to reduce the cohort. Covariates must cover every retained sample. Validate empty intersections and ambiguous IDs. A supplied sample list retains its existing selection and order. Legacy loaders without PGEN sample IDs keep their existing missing-sample-list error. Full-cohort ancestry MAF and additional-genotype processing stay unchanged.

The selected implementation extends existing tasks and scripts. A separate manifest task would add a VM; a JSON input manifest is unnecessary for this four-column table. Optional sample inference uses an internal genotype-ID vector in the shared loader and is active only for the PGEN caller without a supplied list. Provenance records the selection mode, order rule, retained count, and cohort hash.

Test strict manifest parsing, literal URI preservation, reversed chromosome order, File typing and cloud-to-local command rendering, optional sample files, exact explicit-list fits, inferred-versus-explicit intersection fits, bad cohort metadata, existing scientific outputs, both WDL parsers, and installed image scripts. No local Docker build or Terra submission is needed. The complete workflow has not been tested on Terra.
